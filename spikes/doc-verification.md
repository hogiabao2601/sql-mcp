## Could not verify

- **#7 MariaDB `SET SESSION max_execution_time`**: no official page describes what happens. The only evidence is that the variable is missing from the system-variable list (https://mariadb.com/docs/server/server-management/variables-and-modes/server-system-variables). The aborting-statements page (https://mariadb.com/docs/server/ha-and-performance/optimization-and-tuning/query-optimizations/aborting-statements) mentions only the 12.0 hint. Test it in a spike.
- **#3 MySQL FOR SHARE in a READ ONLY transaction**: no page names it. The verdict comes from the "modifying or locking" wording (https://dev.mysql.com/doc/refman/8.4/en/commit.html, https://dev.mysql.com/doc/refman/8.4/en/innodb-performance-ro-txn.html, https://dev.mysql.com/doc/refman/8.4/en/innodb-locking-reads.html).
- **#2 MySQL `max_execution_time` for SHOW / EXPLAIN**: not mentioned in https://dev.mysql.com/doc/refman/8.4/en/server-system-variables.html or https://dev.mysql.com/doc/refman/8.4/en/optimizer-hints.html.
- **#8 PG: changing `transaction_read_only` RO to RW after the first query**: not stated. https://www.postgresql.org/docs/17/sql-set-transaction.html states the "after first query" rule only for the isolation level.
- **#10 PG data-modifying CTE in a read-only transaction**: not mentioned in https://www.postgresql.org/docs/17/sql-set-transaction.html or https://www.postgresql.org/docs/17/queries-with.html.
- **#12 psycopg 3 server-side cursors in autocommit mode**: not stated in the psycopg docs (https://www.psycopg.org/psycopg3/docs/advanced/cursors.html, https://www.psycopg.org/psycopg3/docs/api/cursors.html, https://www.psycopg.org/psycopg3/docs/basic/transactions.html). The verdict uses the PostgreSQL DECLARE rule instead.
- **#17 whether ATTACH inherits the main database's `mode=ro`**: not stated in https://www.sqlite.org/lang_attach.html, https://www.sqlite.org/uri.html or https://www.sqlite.org/c3ref/open.html.
- **#18 that SQL Server has no session-level read-only mode**: no doc states this directly. ApplicationIntent was checked only on the Native Client HA page. The ODBC Driver 17/18 equivalent page returned 404 at `https://learn.microsoft.com/en-us/sql/connect/odbc/odbc-driver-for-sql-server-support-for-high-availability-disaster-recovery` and its `/windows/` variant.
- **#22 psycopg (3) in SQLAlchemy `stream_results`**: not named on https://docs.sqlalchemy.org/en/20/dialects/postgresql.html, which says only "may also be available in others".
